# Проценка

SPA-проект для поиска производителей автозапчастей по артикулу и получения аналогов с ценами и остатками через API «Проценка».

- [Описание API](docs/api.md)
- [Исходные требования](docs/challenge.md)
- API: `http://api.favorit-parts.ru/hs/hsprice/`

## Задача

Приложение решает две задачи:

1. По артикулу получить список производителей, выпускающих эту деталь.
2. По выбранному производителю получить аналоги и предложения с названием, ценой и остатком на складе.

## Возможности

- Поиск производителей по артикулу и переход к аналогам.
- Поддержка артикулов с буквами и спецсимволами: `7160500039S`, `7160500039/S`, `01-89`, `CETA009`.
- Валидация артикула: 2–24 символа, буквы, цифры и `. _ - / # & +`.
- Debounce 400 мс при вводе; поиск сохраняется в query-параметре `search`.
- Загрузка, пустой результат и ошибки API обрабатываются отдельными состояниями.
- Цена берётся из складов, а не из устаревшего `goods.price`.
- Позиции без остатка показываются в конце списка и приглушаются через `opacity: 0.9`.
- Адаптивная вёрстка на Bootstrap 5.3.

## Стек

- React 19 + JSX, без TypeScript.
- Redux Toolkit и React Redux.
- React Router.
- Bootstrap 5.3, SCSS и CSS Modules.
- Zod и react-hook-form.
- Vite+ (`vp`) для dev-сервера, сборки, тестов и проверок.
- Vitest, Testing Library, MSW и Storybook.

## Требования

- Node.js 24+.
- pnpm 12.14.0.
- Docker — опционально, только для альтернативного запуска.

Проект использует pnpm. Команды `npm` и `yarn` в инструкциях не используются.

## Быстрый старт

```bash
corepack enable
pnpm install
cp .env.example .env
pnpm dev
```

Откройте [http://localhost:5173](http://localhost:5173).

Перед первым запуском при необходимости замените демонстрационный ключ API в `src/services/account/use-account.js`. Не коммитьте реальные ключи.

## Запуск через Docker

Docker-образ собран в dev-режиме: исходники монтируются в контейнер, работает Vite с HMR.

```bash
cp .env.example .env
pnpm docker:up
```

Откройте [http://localhost:5173](http://localhost:5173). Остановить контейнер:

```bash
pnpm docker:down
```

`docker-compose.yml` передаёт `.env` в контейнер через `env_file`, поэтому файл `.env` должен существовать до запуска. Порт `5173` проброшен наружу.

## Как пользоваться

1. Введите артикул в поле поиска.
2. Дождитесь списка производителей и выберите нужный бренд.
3. На странице аналогов посмотрите название, производителя, цену и остаток.
4. Позиции без остатка находятся в конце списка и отображаются менее заметно.

## Переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости измените значения.

| Переменная     | Обязательна | Описание                                                |
| -------------- | ----------- | ------------------------------------------------------- |
| `VITE_API_URL` | да          | Базовый URL API, например `http://api.favorit-parts.ru` |
| `VITE_ENV`     | нет         | `development` или `localhost` включает флаг devtools    |

`.env` исключён из git. В репозитории хранится только `.env.example` без секретов.

## Как устроен поиск

### Этап 1. Производители

Приложение отправляет запрос:

```text
GET /hs/hsprice/?key=<key>&number=<article>
```

Из ответа берётся массив `goods`, из верхнеуровневых элементов собирается уникальный список `goods[].brand`. Именно он показывается пользователю.

### Этап 2. Аналоги и предложения

После выбора бренда отправляется запрос:

```text
GET /hs/hsprice/?key=<key>&number=<article>&brand=<brand>&analogues=on
```

В ответе используются как верхнеуровневые `goods`, так и вложенные `goods[].analogues`. Список нормализуется, дубликаты по `goodsID` удаляются.

### Обработка ответа

- Ошибка бизнес-логики приходит объектом `{ error }` даже при HTTP 200 и показывается пользователю понятным сообщением.
- Пустой результат — это `goods` без подходящих брендов; интерфейс показывает пустое состояние.
- `goods.price` устарел и не используется. Цена — минимальная положительная из `warehouses[].price`.
- Остаток — `count`; остаток на конкретном складе — `warehouses[].stock`.
- Спецсимволы в артикуле и бренде кодируются через `URLSearchParams`.
- Устаревшие ответы игнорируются, если параметры запроса уже изменились.

## Структура проекта

```text
src/
  app/            точка входа, провайдеры, роутинг, глобальные стили
  features/       независимые модули
    parts/        поиск, список брендов, аналоги
    utility/      общий layout и страницы ошибок
  services/       логика, общая для нескольких фич
    account/      получение ключа API
  shared/         UI-кит, API, конфиг, эндпоинты, ошибки, ассеты
    api/          обёртка над fetch
    assets/       SVG-иконки
    lib/          общие хуки
    model/        конфиг, маршруты, эндпоинты, ошибки
    ui/           переиспользуемые компоненты
```

Внутри `features/parts`:

- `model/` — слайс, схемы валидации и хуки.
- `ui/` — поле поиска, список брендов, список аналогов и скелетоны.
- `part-brand-list-page.jsx` и `part-list-page.jsx` — страницы маршрутов.
- `index.js` — публичный API фичи.

## Правила разработки

- Направление импортов: `app -> features -> services -> shared`.
- Фичи не импортируют друг друга; общая логика выносится в `services` или `shared`.
- Используется алиас `@/` для путей от `src`.
- Только именованные экспорты, файлы и каталоги в `kebab-case`.
- Компоненты — `.jsx`, логика — `.js`, тесты лежат рядом с модулем.
- Стили: сначала Bootstrap-классы, затем `*.module.scss`; глобальные стили только в `src/app/main.scss`.
- Запросы идут через `@/shared/api`, эндпоинты — из `@/shared/model/endpoints`.
- Асинхронные операции — через `createAsyncThunk`; состояния `idle`, `pending`, `succeeded`, `failed`.
- Компоненты не вызывают API напрямую, а используют хуки фичи.
- Форматирование: 2 пробела, одинарные кавычки, без точек с запятой, ширина строки 100.

## Коммиты

Формат:

```text
type(feature): description
```

Маркеры в описании:

- `+` — новая функциональность.
- `=` — исправление.
- `~` — мелкие правки.

Пример: `=parts: цена из складов и аналоги в списке`.

## Решения и компромиссы

- **SPA без SSR.** Проекту не нужны серверный рендеринг и SEO; достаточно клиентского роутинга.
- **Vite+ как эксперимент.** Проект проверяет единый инструментарий `vp` для dev, build, test и check. Это осознанное решение в рамках учебной задачи, а не обязательный стандарт.
- **Модульная архитектура вместо FSD.** Вместо полного набора FSD-слоёв используются четыре понятных уровня: `app`, `features`, `services`, `shared` с поддержкой саб-модулей.
- **Bootstrap вместо Tailwind.** Bootstrap даёт готовые адаптивные сетки, списки и формы при меньшем количестве собственного CSS.
- **Redux Toolkit.** Состояние поиска и асинхронных запросов явно описано в слайсе; для локального UI-состояния глобальный store не используется.
- **JavaScript без TypeScript.** Ограничение задания; Zod закрывает валидацию входных данных во время выполнения.
